# 正式版 v1.0 启动时序（一页）

> 目标：进程启动即嵌入桌面（可点击）、透明默认开、自动进入文件视图，并且**入场动画只在首帧真正提交后开始**，中间不出现白底或未布局的空帧。
> 实测环境：Release x64 / Windows 11 / 144 DPI；日志 `artifacts/WinUI2Demo-FileView-desktoppane-20261108-231248.log`。

## 顺序（代码与日志一一对应）

```
进程启动
  └─ [STARTUP] t=18ms            pid / OS
窗口创建（隐藏、无重定向位图）
  └─ [STARTUP] t=284ms           window created hidden hwnd=0x...
WinUI 岛内容 + 默认 Page 导航
  └─ [STARTUP] t=443ms           island content set
  └─ [FV] page start             FileViewPage.OnNavigatedTo（枚举已在后台跑）
透明（默认开）+ readback 校验
  └─ [XST] set_IsBackgroundTransparent(True) => hr=0x0 readback=True
嵌入桌面（Progman，Z 序在 SHELLDLL_DefView 之上）
  └─ [DESKTOPPANE] parent=Progman defView=SHELLDLL_DefView hostIsChild=True
隐藏态布局（不 Show）
  └─ [STARTUP] t=457ms           layout done (host still hidden)
页面 Loaded
  └─ [STARTUP] t=516ms           shell Loaded / page Loaded
隐藏态首帧 tick（信息记录，不是显示闸门）
  └─ [STARTUP] t=517ms           Rendering tick#1
显示宿主（内容仍 Opacity=0，透明岛 ⇒ 这一帧只见桌面）
  └─ [STARTUP] t=541ms           host shown contentOpacity=0
5% 幽灵帧（强制一次真正带内容的绘制）
  └─ [STARTUP] t=542ms           firstPaint kick opacity=0.05
等 2 个 Rendering tick + DwmFlush（首帧提交 / 已合成）
  └─ [STARTUP] t=805ms           firstFrame committed ticks=5 dwmFlushHr=0x00000000
入场动画（Composition，240 ms，淡入 0.05→1 + 上移 10→0）
  └─ [STARTUP] t=814ms           anim start durationMs=240
  └─ [STARTUP] t=1096ms          anim complete afterMs=282 visualOpacity=1.00
```

## 为什么这样判“首帧已提交”

| 信号 | 含义 | 用法 |
| --- | --- | --- |
| `CompositionTarget.Rendering` | 该帧**即将提交**（回调发生在提交之前） | 只作“有新帧”的触发，不单独当作已上屏 |
| 第 2 个 Rendering tick | 第一帧的光栅化已经走完（100k 网格首帧约 800 ms，1 个 tick 不够） | 与超时兜底配合 |
| `DwmFlush()` 返回 0 | DWM 已完成这次合成 | 作为“首帧已合成”的确认 |
| `Opacity=0` + 透明岛 | 显示瞬间即使上屏也只见桌面 | 保证不会出现白底/空布局 |

- 可靠性边界：`DwmFlush` 证明“DWM 已合成”，但不等价于“用户已经看到”；在没有逐帧调试器的情况下，这已是可观测的最强信号。
- 超时兜底：隐藏态 tick 最多等 250 ms；显示后等 2 tick 最多 1200 ms。超时打 `[FALLBACK] first-frame-timeout => animate anyway`，动画从 0.05 起播，仍不会闪白。

## 实测时间（热缓存，连续复测）

| 时间点 | 10k | 100k |
| --- | --- | --- |
| 窗口创建（隐藏） | 331 ms | 278–284 ms |
| 页面 Loaded | 744 ms | 516–533 ms |
| 显示宿主（Opacity=0） | 770 ms | 541–545 ms |
| 首帧提交 + DwmFlush | 864 ms | 805–827 ms |
| 动画开始 | 878 ms | 814–835 ms |
| 动画完成（完全可见） | **1158 ms** | **1096–1118 ms** |

- 冷启动会慢（同晚 `anim complete 1863 ms`）；上表只代表热缓存。
- 首帧前已有第 1 批 30 项进入网格，动画淡入的是**已布局内容**；100k 其余批次在动画后继续喂入（`feedDone 994–1017 ms`）。

## 失败与降级

| 失败点 | 兜底 | 日志 |
| --- | --- | --- |
| 透明 API 不可用 | 关闭透明，切深色不透明背景，保持可交互 | `[FALLBACK] transparency-unavailable => opaque island` |
| 桌面嵌入失败 | 恢复 `WS_POPUP + WS_EX_TOPMOST`、`SetParent(null)`、按工作区定位 | `[FALLBACK] desktop-embed-failed[...] => topmost window` |
| 首帧迟迟不来 | 超时后照常播动画（从 0.05 起） | `[FALLBACK] first-frame-timeout waitedMs=1200 ...` |

> 本页记录的三条降级路径本轮**未做故障注入**，只验证了正常路径与日志文案；详见 [OPTIMIZATION.md](OPTIMIZATION.md) 6.6。
